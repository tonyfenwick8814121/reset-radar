# Reset Radar 0.2.0-preview 修复验证

日期：2026-09-09。修复目标来自 0.1.0 独立验收的 R01–R10。结论：**代码与隔离原生场景的发布前门槛通过；需要真实系统、硬件或未来公告的项目继续明确标为未验证。**

## 用户关心的结果

自动重置与手动重置机会现在使用不同的数据和界面流程：

| 类型 | 倒计时含义 | 到点行为 | 恢复监测 |
| --- | --- | --- | --- |
| 自动重置 | 距预计自动重置时间 | 进入“到达预计时间 · 等待确认”，不声称个人额度已恢复 | 用户确认或明确完成公告后立即恢复；24 小时仍未确认则以“未确认归档”结束并恢复 |
| 手动重置机会 | 仅在有明确失效时间时显示“距失效” | 到期写为“已失效” | 到期、标记“已使用”或“不再显示”后立即恢复 |

无日期的手动机会不会伪造 24 小时有效期。它只在有新鲜发布证据时短暂成为当前消息，详情说明有效期未知。应用不读取个人账户，自动重置到点仍需要用户或公告确认。

倒计时统一显示累计小时、分钟、秒。主窗和迷你窗在中英文下均以 `HH:mm:ss` 呈现；100 小时和一周分别显示 `100:00:00` 与 `168:00:00`，不会显示天数或在 99 小时回绕。

## 修复覆盖

- R01–R02：增加时间含义与完整终态，拦截取消、概率预测、玩笑和证据冲突造成的确定倒计时。
- R03：启动、刷新、修订、取消、结束、语言与声音变更统一协调系统待发提醒；退出清理应用自己的待发提醒。
- R04–R05：补 ISO 8601 偏移、Atom 毫秒和嵌套正文解析，分离发布与更新时间；跨来源冲突保持待核实，证据来源不再被相同文本哈希吞掉。
- R06：详情展示原文摘录、链接、产品、人群和历史；增加手动录入、确认、已使用和忽略入口。
- R07：旧设置迁移、未来 schema 拒绝、原子保存、有效备份保护和用户可见存储错误。
- R08：普通失败按 1/2/5/10/15 分钟退避，403/429 与 Retry-After 形成不可被手动刷新绕过的逐源冷却。
- R09–R10：主/迷你窗口分别保存位置并钳制可见范围；补迷你状态文字、双击展开、本地化来源状态与日期对应的时区标签。
- 声音改为应用运行时生成的三音提示，不依赖系统 Glass 音效文件。

## 验证证据

- 项目测试：47/47 通过，使用 `-warnings-as-errors`。
- 独立验收：A01–A26 在全新临时源码副本中 26/26 通过。
- 原生隔离回放：手动机会自然到期、自动到点与确认、100 小时英文显示、迷你展开、手动录入均完成实机操作，见 [修复后原生观察](../qa/results/remediation-native-ui.md)。
- 合成数据只写入临时目录，没有写入用户的 ResetRadar 数据。

## 未验证边界

- 外接屏拔插、Stage Manager、Intel Mac 和 macOS 14/15 玻璃回退。
- 第一条真实未来重置公告的提前量、社区源遗漏率及公告完成关联。
- Developer ID 签名、公证和互联网下载后的 Gatekeeper 安装体验。
