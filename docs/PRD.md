# 归零 · Reset Radar 产品需求

版本：设计 v2，2026-09-09。状态：待开发。平台：macOS 14+，默认简体中文、Asia/Shanghai。

## 1. 产品目标与范围

在公开额度重置公告出现后，尽快告诉用户还有多少准备时间，避免错过临时周额度重置；没有预告时明确报告监测情况。针对当前使用 Mac 的场景，首版选择原生菜单栏应用，Codex 退出或更新不影响其运行。

公开公告与个人账户状态是两类信息。每条公告必须标明产品（ChatGPT、ChatGPT Work、Codex 或未说明）、额度周期（周、5 小时、其他或未说明）、人群和适用条件。不能因为它们使用同一订阅就把一种产品的重置解释为所有产品重置。[核查依据](SOURCES.md)

首版包含：自动获取可接入的公告源；去重和规则解析；时区转换；大悬浮窗、右上角迷你窗、隐藏和退出；声音和本地通知；查询健康状态；中英文；本地时区选择；来源详情、历史和手动录入。

首版不包含：个人账户登录或额度读取、自动领取或消耗重置券、推测下次必然重置时间、手机推送、Windows、AI 常驻监测、云端账号系统。个人常规周额度重置时间不能用公共公告推导。

## 2. 公告入口：默认免费、免登录

根据第二轮反馈，首版改为 **公开 RSS/Atom 订阅**：不要求 X 账号、X API、开发者申请、密钥、充值或自建服务器。本地采集与计时不调用模型。社区服务当前免费提供数据，未来可用性与收费方式由运营者决定；不承诺第三方永久免费。

| 入口 | 首版用途 | 本次核查与边界 |
| --- | --- | --- |
| [ModelYard RSS](https://tibo.modelyard.dev/feed.xml) | Tibo 公告、回复与重置机会的社区转引来源 | 匿名读取成功；样本包含原文片段、原帖链接与分类。分类可能把 banked reset 归成普通预告，必须重新核对文本 |
| [Codex Reset Atom](https://codex-reset.com/feed.xml) | 第二社区来源、历史与原帖链接 | 匿名读取成功；其 Atom 与 JSON 数据并非完全同步，不能假设订阅涵盖每条最新帖子或全部更正 |
| [OpenAI News RSS](https://openai.com/news/rss.xml) | 官方补充来源 | 免费；不能保证出现每次临时重置 |
| [OpenAI Status RSS](https://status.openai.com/history.rss) | 故障与补偿线索 | 免费；服务恢复本身不等于额度重置 |
| 用户粘贴公告文本/链接或导入事件文件 | 未支持表达与覆盖缺口的补救 | 标记手动录入；确认产品、人群、日期和时区后建立用户确认的计时 |

普通公开订阅链接由应用预置，用户无需配置任何 API。另已核查到 Codex Reset 的免费公开 JSON `/api/feed`，无需密钥；这是第三方公开数据接口，不是用户付费调用 X API。它可作为后续增强：补充原始帖子和上游抓取时间。首版纯 RSS/Atom 即可工作，不把 JSON 或付费 X API 作为前置条件。

暂不采用 codexreset.app 的概率预测作为预告。其 feed 混有 GitHub 热度、故障和模型概率，不能由“71%”“预计 24 小时”等信息计算确定重置时间。未来添加其他社区时也沿用这一规则。

来源读取成功、来源是否保持采集、事件内容是否真实是三个维度。社区文章的 `pubDate` / Atom `updated` 不一定是 Tibo 原始发帖时刻；缺原始时间和语境时区时，不能用它解释“明天”。RSS 很久没有新条目不等于采集故障，HTTP 200 也不证明上游仍在更新；无法验证上游时显示“订阅可访问 · 上游采集状态未知”。

新条目通过产品、重置类别、原帖身份/链接、时间与适用范围解析。单一社区转引可作为提醒线索；有明确时间且无冲突时可以显示标注“社区转引”的预计倒计时，不冒充官方已核实。摘要与引用原文冲突、原帖身份不清、不同来源时间矛盾时进入待确认。多个站点转引同一帖子合并证据，不视为多个独立官方证实。

首次打开先显示“尚未完成首次查询”，随后显示实际成功读取的来源和最近检查时间。全不可用时显示“查询失败”，不是“暂无预告”。不抓登录后的 X 页面，不要求浏览器常驻，不绕过站点访问限制；社区页面 403 时只能使用该站明确公开的订阅入口，不能绕过页面限制。

## 3. 公告状态与准确性

事件状态和查询健康状态独立，断网不能抹掉已保存倒计时。

| 事件状态 | 大字/主文案 | 行为 |
| --- | --- | --- |
| 尚无结果 | 尚未完成首次查询 | 不显示“没有预告” |
| 无已知预告 | 暂无明确重置预告 | 小字显示已接入来源覆盖范围、最新查询和结果 |
| 有线索、时间含糊 | 有重置消息，时间待确认 | 显示原意，例如“预计明天，尚未公布具体时间”；不编造秒级倒计时 |
| 有明确未来时间 | `12:34:56` | 小字“预计北京时间 9 月 10 日 05:00 重置”；超过 99 小时显示天数+时分秒 |
| 大致时刻 | `约 12:34:56` | 保留“约”；范围时间显示起止窗口，不伪装成单点确定时刻 |
| 到达预计时间 | 已到预计时间 · 等待确认 | 计时不变负数，不据此宣称个人额度到账 |
| 来源宣布完成 | 已宣布重置 | 小字“请在账户中确认是否生效”；保留公告人群 |
| 发放可手动使用的重置机会 | 有重置机会可使用 | 与自动重置分开；仅有明确到期时间才显示“距失效”的倒计时 |
| 更正或取消 | 重置时间已更新 / 预告已取消 | 取消旧提醒，更新同一事件；重要变更单次主动提醒 |

规则不能确定含义时进入待确认，用户可打开原文并手动设置。对疑似相关但不含明确 reset 语义的幽默表达，只能显示线索。规则引擎首版不承诺识别全部自然语言。

产品默认关注所有相关产品，人群未知也保留消息并标记“适用范围未说明”。用户可在设置中选择关注产品和订阅套餐；明确不匹配的事件保留在历史但不弹窗，范围未知不当作明确匹配。

多事件同时存在时，主窗展示最近的适用未来事件，并显示“另有 N 条”。未定时事件单独显示提示，不能覆盖一个已有准确倒计时。

## 4. 时间与提醒

内部存 UTC 时间，显示使用 IANA 时区。默认 `Asia/Shanghai`，设置可搜索全部系统时区，并提供北京、东京、新加坡、洛杉矶、纽约、伦敦和跟随系统。语言与时区互不绑定。

原文的 PT 只有在日期明确时按 `America/Los_Angeles` 的夏令时规则换算。PST、PDT 保留原始表达；在夏季写 PST、日期缺失、含糊的 CST、DST 重复/不存在时刻等场景，不静默猜测。`tomorrow` 必须相对原始发帖时刻和有证据的发帖语境时区，不能相对抓取日期或中国日期。

首次发现适用新预告：立即居中显示折叠主窗、置顶，并播放约 2 秒柔和提示音。默认额外提醒点为提前 30 分钟、5 分钟、到点；设置提供 60/30/10/5 分钟开关。若首次发现距重置不足 5 分钟，只发一次合并提醒，禁止连续补发已错过的多个节点。

首次安装读取订阅历史时先建立基线：已经过去的预告、历史完成公告和无法确认仍有效的重置机会只进入历史，不逐条弹窗或播放声音。仍明确位于未来且适用的预告可立即显示，多个结果合并成一条发现提醒。没有有效期/当前可用证据的旧重置机会不能仅凭首次抓到就变成“新机会”。

第一次提醒使用大窗；用户收起后，同一事件的例行节点尊重其迷你/隐藏选择，使用迷你强调或系统通知与声音。新事件及时间更正/取消默认再次居中一次；设置可关闭主动展开。相同内容重复抓取、翻译、重启或断网恢复不重复提醒。

声音默认低音量、短旋律、不循环，可静音、试听和停止；使用原创合成音，不依赖音乐平台。夜间免打扰可选，默认关闭以满足主动提醒；开启后推迟主动弹窗和声音，保留界面更新。系统音量、专注模式、通知授权可能影响系统通知和声音，应提供可测试的设置状态。

锁屏、系统安全界面、睡眠期间无法保证中央浮窗可见。应用不强制唤醒电脑；唤醒/解锁后立即校正倒计时并补发一条仍有意义的提醒。电脑关闭时本地采集停止；这是独立本地应用的边界。

## 5. 悬浮窗交互和视觉 v2

核心目标是余光可辨识变化：同时改变状态色、背景染色、图标和文字层级，不只改变一句小字。大数字不随透明度降低而变淡。

| 状态 | 视觉与主文字 |
| --- | --- |
| 明确预告 | 琥珀色玻璃染色、闪电图标、“重置预告”、约 70 pt / 650 等宽数字 |
| 剩余 ≤5 分钟 | 珊瑚红、加粗数字；强调一次，不持续闪烁 |
| 重置机会 | 翡翠绿、礼物图标、约 36 pt / 750 “有重置机会”；保留“部分用户，账户中确认” |
| 暂无预告 | 灰色、轻字重约 29 pt、月牙图标，低干扰 |
| 时间待定 | 淡紫色、时钟图标、“时间待确认”；不生成伪精确倒计时 |
| 到点待确认 | 低饱和金色、时钟图标、“等待重置确认” |
| 查询失败 | 独立红色健康标记与文字；不覆盖已知事件的主色和倒计时 |

- 主窗默认折叠，约 412 × 294 pt、圆角 28 pt。显示标题栏、状态、计时/消息、预计本地日期时间和一行最新查询结果。移除“小时/分钟/秒钟”三个单位标签。
- 底部中央下拉箭头展开适用范围、社区转引说明、来源按钮、查询按钮、最近完整成功及覆盖状态；同一个箭头朝上时可收起。初次打开和新事件默认折叠；语言和时区切换不重置折叠状态。
- 「中 / EN」固定放在浮窗右上角，选中语言有底色。大窗和迷你窗均可直接切换；不藏在网页外层导航或设置页里。
- 首次显示及新预告在当前交互屏幕的可见区域中央，位于普通应用之上；跨 Space/普通全屏需真机验证，不能覆盖系统安全界面。
- 标题区域可拖动，文本输入焦点留在原应用；标题栏提供关闭、隐藏、缩到右上角和设置。展开详情与缩成迷你窗是两个独立操作。
- 右上角迷你窗约 260 × 145 pt，距当前屏幕可见区域顶/右各 20 pt，保留状态色/图标、时间、当地日期时间、查询结果、语言切换和展开按钮。
- 迷你窗可拖动、双击展开；拔出外接屏时回到可见范围。关闭窗口/隐藏继续监测，菜单栏“退出归零”才停止。Esc 隐藏；从菜单栏恢复。
- macOS 26+ 用 SwiftUI `glassEffect` 或 AppKit `NSGlassEffectView` 实现系统 Liquid Glass；macOS 14/15 采用 `NSVisualEffectView` 毛玻璃回退。框架 availability 在构建时验证；最低系统版本仍为 14。
- 玻璃外框使用细边缘高光、适度背景模糊与状态染色；不把整个内容反复动画。折叠/展开约 280ms；重要事件出现时顶边高光只强调一次。系统减少动态效果时关闭动画；降低透明度时用实色底，状态色和文字仍保留。
- 浅色/深色都必须检查；纯数字用等宽排版避免抖动，时间每秒重算，隐藏时停止重绘。图标有中英文辅助名称；折叠内容不可获取键盘焦点。正式应用查询时间/标签建议至少 11–12 pt，可按系统文字大小调整。

浏览器原型是 CSS 玻璃外观模拟；真实的系统折射、窗口层级、动画手感与壁纸混合仍需原生应用真机验证。[Apple Liquid Glass](https://developer.apple.com/documentation/appkit/nsglasseffectview)

## 6. 监测频率、健康与成本

本地定时器执行普通 HTTP 请求，**运行时模型 token = 0，ChatGPT/Codex 对话额度消耗 = 0**。免费路径增加抓取频率影响网络流量、源站负担与电量，不会天然增加模型消耗。

| 场景 | 免费社区订阅 | 官方补充源 |
| --- | --- | --- |
| 无预告、有预告或临近重置 | 默认每 5 分钟一次，遵守服务端缓存与限流 | Status 15 分钟，News 30 分钟 |
| 唤醒、恢复联网、手动刷新 | 合并触发一次；有效缓存仍使用缓存，不添加随机参数绕过缓存 | 同样合并 |
| 如以后启用支持更快刷新的免费 JSON | 无预告 5 分钟、目标前 6 小时内 2 分钟、目标前 30 分钟至后 15 分钟 1 分钟；实际请求间隔不短于服务端缓存要求 | 原频率 |

倒计时和提前 30/5 分钟、到点提醒全部由本地时钟执行，不依赖网络轮询，也不需要每秒抓取。两个社区源全天运行约 576 次 HTTP 请求/日；不产生 API 或模型账单（正常网络接入成本另计）。

本次两个订阅都返回约 5 分钟缓存，Codex Reset 还允许 stale-while-revalidate；把同一缓存接口每分钟请求一次不代表内容更及时。因此 v2 免费模式不承诺 1 分钟发现公告。实际延迟由上游采集/审核、服务端缓存与客户端轮询共同构成；可能超过 5 分钟，也可能漏报。正式接入阶段记录原帖→订阅→客户端的时间差。

一次请求超时 15 秒。失败按 1、2、5、10、15 分钟退避，尊重更长的 Retry-After；403/需登录/收费切换时暂停该源并标记，绝不自动购买或替换为付费调用。其他来源继续。连续两次请求失败或超过两倍本地计划周期未成功则标记客户端连接过期；不能用条目发布时间替代客户端查询时间。

折叠主窗保留 `最近查询 18:42:08 · 部分失败`，展开后显示日期、最近完整成功、各源覆盖与错误。详情逐源区分 lastAttemptAt、lastTransportSuccessAt 和可选 upstreamFetchedAt；没有上游时间时显示“上游采集状态未知”。200 登录页、XML 解析失败不能算成功；304 只能刷新传输成功时间，不能刷新上游采集时间。

免费默认路径不含 X API、开发者凭据或服务端模型调用。未来若用户明确需要付费直连 X，再单独加可选适配器、钥匙串与预算设置，不构成 v2 的功能或发布门槛。

## 7. 独立运行与开源交付

选择 SwiftUI + AppKit 原生 `.app`，常驻菜单栏。URLSession 拉取、Foundation 时间处理、本地 JSON 原子保存、系统本地通知。首版不依赖 Codex 插件、私有数据库、内部接口或自动化任务。

应用需保持运行，可选登录启动。关闭 Codex、升级 Codex、切换模型都不影响计时器。配置及缓存保存到独立的 Application Support 目录。首版更新通过下载新版本替换应用，保留用户数据；暂不引入自动更新框架。

用户选择菜单栏“退出归零”时取消尚未送达的系统本地提醒，再退出应用；仅隐藏或关闭窗口时保留提醒。下次启动基于持久事件重新安排尚有效的提醒。异常崩溃无法保证执行退出清理，系统已经登记的提醒可能继续出现；重启后统一核对和去重。

计划以 MIT 开源代码，通过 GitHub Releases 提供安装包、校验和、中英文说明和源码构建方式。发布面向他人的 macOS 安装包应完成签名及公证；依赖开发者证书。没有证书时只能明确标记本地/开发构建，不能称为已公证的一键安装版。GitHub Actions 用于构建与检查，不充当实时监测调度器。

## 8. 成功标准

准确时间的确定性夹具全部通过；含糊时间不产生伪精确倒计时。健康情况下符合轮询频率；每事件每提醒节点最多通知一次。空状态和全部/部分失败不会混淆。关闭 Codex 后仍能发现模拟公告、计时和弹窗。中英文、非中国时区、全屏桌面和睡眠恢复在真机验证。

性能目标（待实测）：安静状态平均 CPU <1%，常驻内存 <100 MB，隐藏时无每秒 UI 刷新。显示倒计时每秒更新且不累积漂移；达成情况须在发布记录中给出实测环境与结果。
